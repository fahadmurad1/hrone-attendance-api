# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Static dummy response; does not verify MongoDB connection. | Returns `200 OK` even when MongoDB is offline or unreachable, failing the readiness probe contract. | Implemented `client.admin.command("ping")` and return `503 Service Unavailable` with `{"detail": ...}` if an exception occurs. |
| 2 | Global setup / Startup (lines 20–28) | No indexes created on startup; relies solely on default `_id`. | Seeded database queries execute full collection scans (`COLLSCAN`), failing performance benchmarks and `/admin/explain` index checks. Also fails concurrency guarantees. | Added a FastAPI `lifespan` context manager that idempotently creates unique indexes (`emp_code` on `employees`, `(emp_code, date)` on `attendance_logs`) and compound query indexes. |
| 3 | `create_employee` (lines 79–83) | Check-then-insert race condition (`find_one` followed by `insert_one`). | Concurrent POST requests with the same `emp_code` both pass the check and attempt insertion, causing unhandled 500 errors or duplicate records. | Backed by a unique database index on `emp_code`, catch `pymongo.errors.DuplicateKeyError` and raise `HTTPException(409, "emp_code already exists")`. |
| 4 | `EmployeeIn` model (lines 53–60) | Missing schema validations: `emp_code` pattern, email regex, and `shift_start != shift_end`. | Invalid inputs such as `shift_start == shift_end` or malformed employee codes return 201 instead of 422 Unprocessable Entity. | Added Pydantic v2 `Field` pattern constraints (`^EMP\d{4,6}$`, email regex) and a `@model_validator` ensuring `shift_start != shift_end`. |
| 5 | `create_employee` (lines 82–85) | Naive local time used (`datetime.now()`) and raw datetime returned. | Stores un-anchored local time in Mongo; returns ISO string in response rather than integer epoch milliseconds (`EpochMillis`), failing contract schema. | Store timezone-aware UTC BSON datetime truncated to seconds; return integer epoch milliseconds via `datetime_to_epoch_ms`. |
| 6 | `list_employees` (line 93) | Off-by-one pagination skip formula: `skip = page * page_size`. | Requesting `page=1, page_size=20` skips the first 20 records (items 1–20 are skipped; items 21–40 returned). | Corrected formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (line 94) | `total` counts the unfiltered collection: `count_documents({})`. | Querying with `?department=Engineering` returns total count of all employees across all departments instead of filtered count. | Passed filter query `q` into `count_documents(q)`. |
| 8 | `list_employees` (line 95) | Missing sort order in cursor query. | Employees are returned in arbitrary insertion order rather than sorted by `emp_code` ascending. | Added `.sort("emp_code", ASCENDING)` to the Mongo query. |
| 9 | `punch_in` (lines 101, 113) | Missing check for non-existent employee; causes unhandled `TypeError`. | Calling punch-in with unknown `emp_code` evaluates `emp["shift_start"]` on `None`, crashing with 500 instead of 404. | Added explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in` (line 102) | Naive timestamp parsing without IST handling; milliseconds not truncated (R1). | Running on non-IST server misallocates calendar dates; sub-second precision leaks into calculations violating R1. | Convert input instant to UTC datetime, truncate microseconds, and project into IST (+05:30) for calendar and shift math. |
| 11 | `punch_in` (line 103) | Overnight shift calendar date allocation broken (R1). | For shifts like 22:00–06:00, punching in at 05:00 IST assigns `date` to current day instead of the previous day when the shift started. | Implemented `get_attendance_date` helper that shifts date back by 1 day if `shift_end <= shift_start` and punch-in time is before `shift_end`. |
| 12 | `punch_in` (lines 104–118) | Check-then-insert race condition. | Concurrent punch-ins for the same employee and date both pass `find_one` and create duplicate documents or raise 500. | Enforced compound unique index `(emp_code, date)` and caught `DuplicateKeyError` to return `HTTPException(409)`. |
| 13 | `punch_in` (lines 119–121) | Injects invalid `"id"` and returns unformatted datetime objects. | Response violates `AttendanceRecord` schema (which forbids `id` and requires epoch milliseconds for `punch_in`). | Removed `"id"` field and serialized BSON dates to integer epoch milliseconds. |
| 14 | `compute_late_minutes` (lines 33–37) | Grace period boundary bug (R2) and overnight shift failure. | `09:40:01` has elapsed seconds 601 (minutes floor = 10); starter's `minutes > 10` returned 0 instead of 10. Also compared against today's start for overnight shifts. | Checked `(punch_in - shift_start).total_seconds() > 600`, returning floor whole minutes since `shift_start` referenced to the correct IST shift start datetime. |
| 15 | `compute_overtime` (lines 44–47) | Overtime under 30 minutes was not zeroed out (R3); overnight end date miscalculated. | 15 minutes past shift end returned 15 instead of 0. Overnight shifts evaluated against shift start date, creating 20+ hours phantom overtime. | Fixed to return `minutes if minutes >= 30 else 0`, referencing the overnight shift end date (`date + 1 day`). |
| 16 | `compute_work_hours` (lines 40–42) | Built-in Python `round()` uses round-half-to-even (banker's rounding) instead of round-half-up (R4/R8). | `2.675` hours rounded down to `2.67` instead of `2.68`. | Implemented `round_half_up` helper using Python `decimal.Decimal` with `ROUND_HALF_UP`. |
| 17 | `list_attendance` (lines 144–147) | Loads entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorts in Python. | On ~100k records, causes massive latency and Out-Of-Memory (OOM) crashes. Also missed secondary sort on `emp_code`. | Delegated sorting and pagination directly to MongoDB engine via `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(...).limit(...)`. |
| 18 | `list_attendance` (lines 125–132) | Missing date range validation. | Passing `date_from > date_to` returned 200 with an empty list instead of `422 Unprocessable Entity`. | Added validation: `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 19 | `list_attendance` (lines 148–150) | Injected `"id": str(d.pop("_id"))`. | Mutates records and violates `AttendanceRecord` schema. | Removed `"id"` generation and serialized document strictly according to OpenAPI contract. |
| 20 | `PunchInIn` model (lines 63–67) | Missing validation on `status`. | Allowed non-presence status values like `ABSENT` or `LEAVE` to be punched in. | Restricted `status` to `PresenceStatus` enum (`PRESENT`, `WFH`, `ON_DUTY`). |

---

### Non-Defects Examined
1. **Natural Key Addressing:** The absence of a synthetic primary key (like `id` or `_id`) on attendance records was examined. Per `DATA_MODEL.md`, attendance records are addressed naturally by `(emp_code, date)`, which is correct.
2. **Environment Precedence:** Using `load_dotenv(override=False)` ensures that while local developers can use `.env`, system environment variables injected by test runners (`MONGO_URI`, `MONGO_DB`) take full precedence.
3. **BSON Datetime vs Epoch Milliseconds:** Storing native UTC BSON datetimes in MongoDB while accepting/returning integer epoch milliseconds in HTTP payloads is the intended design specified in `DATA_MODEL.md`.
